## Two-stage report + RAG (retrieval preliminary) status
- Hybrid retrieval, no new model: structured vector (role, metric, pattern, status, values) 0.7 + TF-IDF over report text 0.3, filtered to the same role and metric (`backend/retrieval.go`).
- Preliminary = rules report from the LIVE values (numbers never come from old reports) + the retrieved report's wording; severity = max(rules, retrieved) so it never under-alerts. Label "Preliminary - based on N similar past incidents (best match X%, INC-...) - full AI report coming". No match -> "Preliminary from the rules - full AI report coming".
- Library: every live AI report is added automatically + 254 seed reference reports written by rsn_v1 on the training split (320 generated, 254 passed the gate), ranked 3% below live reports.
- Deploy check (RAG_STATUS.md): 4/4 incidents had the preliminary at 0 s, the AI report replaced it on the same incident, retrieval matched 2/4 (others used rules). Seed library deploy PASS.
- Consistency check: after the AI report, it is compared with similar past incidents and a disagreement is logged ("AI severity sensor_fault differs from 1 of 3 similar past incidents").
- New today: the checklist is built from the preliminary; operators can acknowledge and tick while the AI writes; the AI report merges in (ticked steps it repeats stay done, dropped open steps are withdrawn, new ones marked "New since you acknowledged"). Close/dismiss wait for the AI report.

## Conversational interface (later; path)
- The reasoner rsn_v1 was trained with ~2,000 chat tool traces (SPEC D5, data C chat). Chat tools in training: count_incidents, find_incidents, get_action_history (+ incident tools). Score above.

Plan: (1) endpoint + tools reading the store, (2) UI panel with the incident context, (3) guard: answers must quote tool numbers (numbers_exact check), no actuation, (4) board test: latency per answer and the 100-question chat dev set on the board.

## Safety / robustness
- Policy gate (JSON, enums, evidence ids, numbers must exist in the input, no actuation language), post-rules, severity guard (AI may not say normal when rules say warning/critical), human approval, deterministic fallback.
- htpd_v8x3: 150 s wall-clock guard per report, bounded token picking, heartbeat stall log; overnight watchdog: 0 stalls.
- Rollback scripts for every deploy; known-good snapshots.
